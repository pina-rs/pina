# Name decode failures and stop Dart clients from skipping the version check

A fixed-account decode failure now reports what actually failed instead of collapsing every case into `InvalidAccountData`. A length mismatch returns `PinaProgramError::InvalidAccountSize` (`0xFFFF_FFFB`) and a discriminator mismatch returns `InvalidDiscriminator` (`0xFFFF_FFFF`) across `validate_account_data`, `try_from_bytes`, `try_from_bytes_mut`, `assert_type`, and the readers generated by `#[account]`, `#[instruction]`, and `#[event]`. Instructions and events keep `InvalidInstructionData` for a length mismatch, since they describe payload bytes rather than an account size. A stale or future migration envelope already reported `MigrationRequired` and `InvalidMigrationVersion`; those codes now stay distinguishable from a structural failure, which is what makes an envelope change diagnosable from a client instead of looking like generic corruption. `parse_instruction` still remaps the discriminator's own error to `InvalidInstructionData`, and its documentation now records that envelope errors never reach that path.

Generated Dart clients fail closed when an account the IDL marks as envelope-aware has no migration-version read to harden. The hardener previously treated "statement not found" the same as "already hardened" and shipped the generic constant decoder unchanged, so decoding could silently skip the version check, mirroring the JavaScript hardener's generation-time assert.
