# Add `#[derive(PodEnum)]` for unit enums

Adds a `PodEnum` derive macro that generates zeropod trait impls for unit enums with explicit discriminants, enabling their use as fields in `#[account]` structs and other pod types.

```rust
use pina::PodEnum;

#[derive(PodEnum)]
#[repr(u8)]
enum Color {
	Red = 0,
	Green = 1,
	Blue = 2,
}

#[account(crate = ::pina, discriminator = MyAccount)]
struct Palette {
	color: ColorZc, // zero-copy companion generated by the derive
	brightness: PodU64,
}
```

The derive generates a `ColorZc` zero-copy companion (`#[repr(transparent)]` over `[u8; N]`, alignment 1) that:

- validates the discriminant at the deserialization boundary (`ZcValidate`, `ZcElem`),
- implements `ZeroPodSchema` / `ZeroPodFixed` for the enum with `type Zc = ColorZc`,
- implements `ZcField` mapping the enum to its companion,
- provides ergonomics: `From<Enum>`, `try_to_enum()`, `is()`, `PartialEq<Enum>` / `PartialEq<primitive>`, `Display`, and `Debug`.

Requires `#[repr(u8)]`, `#[repr(u16)]`, `#[repr(u32)]`, or `#[repr(u64)]` with all unit variants carrying explicit discriminants. Supports `#[pina(crate = ::pina)]` for renamed dependencies.

Because the enum's validity is bit-pattern-restricted at the Rust type level, the enum itself is the _schema_ type; account structs store the `EnumZc` companion as the field type (invalid discriminants are rejected before any reference to the enum is formed).
