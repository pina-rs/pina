# Security sweep — 2026-09-19 (evening)

Owner-authorized adversarial sweep of the pina workspace, run 21:55–02:00 BST against `feat/abi-version-reset` @ `3f7d38f9` (worktree branch `security-sweep-2026-09-19`). Method: four static deep-reads (runtime core, macro codegen, migration machinery, `pina_abi`) plus six dynamic red-team batteries that deployed real SBF artifacts of the examples into offline Surfnet instances (`pina_test::ProgramTest`) and executed ~120 adversarial instruction sequences. All 25 example artifacts were built in this worktree; attack crates are retained under `tmp/sweep/` (gitignored).

Prior art (`security/deep-audit-2026-09-18*.md`) was treated as ground truth: agents re-verified several of its remediations landed and hunted only new holes.

## Verdict

**No Critical. Five new Medium findings, all confirmed by execution or host probe — one a working fund-drain against a shipped template, two governance-guard asymmetries in the multisig (a proposal whose approvals re-bind to the wrong members and a spending limit that outlives removal), and two framework-level parsing gaps that the 2026-09-18 audit had marked "verified sound". The migration machinery — tonight's centerpiece — held under a 21-scenario dynamic battery with zero exploits.** The remainder is a Low/Info tail concentrated in one family: attacker-chosen PDA bumps (the documented-but-unlinted `CreateProgramAccountWithUncheckedBump` idiom) and example-template hygiene.

## Framework work orders (priority order)

1. **RC-1**: cursor must track consumed writable slots (retain consumed-slice bounds or a macro-generated pairwise pre-pass over the full writable set). Add UI/host pins for the `[&T, &mut T]` same-address shape.
2. **N2 (macro)**: compile-time reject of non-trailing optional accounts (the failure is currently a silent runtime shift). New lesson candidate for `security/`: optional-slot confusion.
3. **E2/E1 (multisig template)**: give `VaultExecute` and `ConfigExecute` the same `is_expired` + stale-transaction guards every other path enforces; on member removal, either freeze affected proposals or re-check approvals against the post-removal roster instead of trusting the mask. **E3**: make spending-limit removal part of member removal (or bind limits to the multisig roster).
4. **ECON-F1 (template)**: `Deposit` must `TransferChecked` stake into `stake_vault` (and `Withdraw` out) + a `stake_vault == total_staked` invariant assertion in the suite. Detailed reproduction and fix sketch in `dynamic-economics.md`.
5. **N1 (macro)**: single ordered seed vec so codegen and IDL agree; expansion-snapshot UI test.
6. **pina_abi ABI-F1/F2**: **FIXED on this branch** (`crates/pina_abi/src/lib.rs`: `ContractHistory::validate` now rejects non-identifier and raw-identifier `rustName` values with a typed error before the macro's `syn::Ident::new` can panic, and `DataSchema::validate` rejects duplicate field names per version; 4 tests added, `pina_abi` 141/141 and `pina_macros` 62/62 green). Still open: a `manifest_decode` fuzz target (existing targets cover only on-chain decoders).
7. **Migrations**: executor pre-zero of the grown region as defense-in-depth (dynamic probe shows the stack already commits zeros — blocks nothing today); `MAX_INLINE_STEPS` configurable in `pina.toml` (or document the repeated-`[0xFF]` client ladder); `pina migrations verify` CI command; fix the example's funding cap.
8. **Template hygiene**: replace the prop_amm hardcoded uniform-seed authority (or document it as fixture-only); fix the stale staking header and counter layout docs; unique `declare_id` per example; zero-address guard on authority rotation.
