# Cross-ecosystem audit research — 2026-09-19

Research conducted during the remediation review to cross-check the audit's coverage against finding classes documented in public security audits of Solana programs and EVM protocols. Two passes: Solana-side audit reports (Squads, Anchor-derived classes, SPL/core post-mortems, 2023–2026 incidents) and EVM-side audit classes translated to Solana surfaces (OpenZeppelin ERC-4626, Uniswap v1–v4, Compound governance, Audius, Balancer 2025, dForce read-only reentrancy). Sources are named per class; the translation to pina's surfaces is analysis, not a claim about the cited reports.

## Classes the research surfaced as open items (none block this PR)

1. **Two-step authority rotation** (OpenZeppelin `Ownable2Step`; standard audit recommendation). The repo already tracks this: `role_registry_program`'s one-step `RotateAdmin` is flagged in `incidents-2023-2026.md` as blocking the planned `two-phase authority rotation` lint. Research reinforces the priority: a mistyped single-step rotation bricks custody with no recovery path on Solana. Existing decision stands — upgrade the example before the lint lands.
2. **Delay envelope on privileged operations** (Compound timelock; ToB Balancer "secondary controls"). Lesson 11 documents pause guardians and per-window caps; a generic `queued_at`/delay envelope primitive in the framework is a design candidate, not a defect.
3. **Fee-on-transfer awareness in generated CPI** (Uniswap v4's CELO dual-representation finding). Pina templates already use `TransferChecked` and measure vault deltas rather than trusting amounts; a lint denying plain `Transfer` when the mint carries `TransferFeeConfig` is a plausible future rule since loaders can read the extension set.
4. **Batched-operation amplification of rounding dust** (Balancer batch-swap lesson). Staking floors bank dust into `pending_rewards` (it stays claimable), so dust is not lost; the general guidance — invariant tests across claim→re-stake→claim sequences — is a harness-design note for future Kani work.
5. **Min-out slippage parameters on mints/claims** (EIP-4626 guidance). Not applicable to the current templates (no share minting), relevant if a share-based pool template is added.

## Verdict

The remediation's designs hold up against both research passes: the rewards-per-token rewrite is structurally immune to the donation/inflation class because accounting never reads vault balances, the vesting floor direction matches the EIP-4626 rule, and the migration/borrow-guard machinery maps onto the Audius and dForce classes respectively. The self-audit of the changed code found two real gaps — a dead error variant the IDL advertised but no path returned, and a misleading checksum-404 message — both fixed in this PR. The five open items above are documented future work, consistent with the repo's existing incident-research conclusions.
